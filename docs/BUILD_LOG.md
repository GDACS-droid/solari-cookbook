Replaced that assumption with a standard-library ZIP validator enforcing one exact entry, no traversal/encryption, 60 MB compressed and 400 MB expanded ceilings. The next real run completed end-to-end in about 46 seconds.
- **Privacy hardening:** no City customer/account/name/service-address fields are requested; no DOR owner/mailing fields leave the Sandbox. Raw provider Browser/Sandbox handles are replaced with one-way 12-character run references before SSE output.
- **Honest event semantics:** the current City row is source-reported active but dated February 2022; the table has no 2026 active event. Score is 10, with zero fake recency/equity points. Fresh court/foreclosure/tax/title facts stay unavailable.
- **Verification after implementation:** source-policy check, lint, TypeScript, 23 tests, production build, 6 desktop/mobile E2E tests, full-page desktop/mobile inspection, and a real current-key Solari Browser + Sandbox run all passed.
- **Adversarial repair and second real proof:** independent reviewers found that the historic City row was typed `NEW_LIEN`, the DOR parser accepted first-match/line-oriented CSV, direct reads lacked bounded retries, curl followed redirects, and client cancellation did not actively terminate remote work. Replaced the event with non-new `LIEN_STATUS_ACTIVE`; moved to a strict RFC-4180 parser with unique required headers, full-schema hash, and exact-one-row enforcement; added bounded retries/deadlines, no-redirect DOR retrieval, and abort-triggered Browser/Sandbox cleanup. Retries are now explicit physical attempts enforced by generated budgets (DOR 4, City 2), route setup handles an already-aborted request, and Browser/Sandbox creation rechecks cancellation and destroys a just-created resource before any source navigation or command. Budget-exhaustion and route pre-cancel regressions are covered.
